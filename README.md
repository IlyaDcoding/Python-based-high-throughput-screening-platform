# HEC-DB Screening Platform

Курсовой проект по **Fundamental Numerical Calculations**, тема 7. Приложение проверяет данные о керамических образцах, отбирает сопоставимые измерения, применяет ограничения по свойствам и строит рейтинг кандидатов для выбранного применения. Первый сценарий исследует материалы для thermal barrier coatings (TBC).

## Быстрый запуск

Нужен Python 3.10 или новее. Команды для Windows PowerShell из корня проекта:

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m hec_screen validate data/hec_measurements.xlsx --output runs/validated
.\.venv\Scripts\python.exe -m hec_screen screen data/hec_measurements.csv --config configs/tbc.json --output runs/demo --top 3
~~~

В macOS/Linux замените путь к интерпретатору на .venv/bin/python. После установки зависимостей сеть для запуска не нужна. Каждый запуск сохраняет результаты в новую папку. Для повторного опыта укажите другое значение --output. Полный список опций доступен через python -m hec_screen --help и help соответствующей подкоманды.

## Импорт и сценарии

Для обмена используйте CSV в UTF‑8 с запятой или XLSX со значениями. Многолистовой Excel читается с листа Measurements, если он есть. Иначе используется первый лист. Конкретный лист можно указать через --sheet. Файлы с формулами нужно сохранить как значения. Канонические заголовки можно скопировать из набора данных. Подробности полей, единиц и допустимых пропусков приведены в [описании данных](docs/data.md).

Если у другой группы свойства записаны в столбцах, настройте [пример mapping](configs/wide_mapping.example.json) под её заголовки и происхождение данных. Блок columns связывает поля со столбцами. Блок defaults задаёт константы. Для каждого свойства отдельно сопоставьте значение, единицу, условия и ссылку на место в источнике. Преобразуйте широкую таблицу и передайте оба файла в screen:

~~~powershell
.\.venv\Scripts\python.exe -m hec_screen validate peer.xlsx --sheet Data --mapping configs/wide_mapping.example.json --output runs/peer
.\.venv\Scripts\python.exe -m hec_screen screen data/hec_measurements.csv runs/peer/measurements.csv --config configs/tbc.json --output runs/merged
~~~

Для другого поиска измените JSON-сценарий. family, application и material_class задают необязательные точные фильтры без учёта регистра. Кандидат проходит фильтр application, если это назначение есть у любого его наблюдения выбранного происхождения. Поле origin выбирает один тип данных для всего запуска. Критерий задаёт property, direction (min/max), weight, необязательные включительные min/max в канонических единицах и cohort. Для нескольких серий укажите одну согласованную cohort на критерий. Вес 0 позволяет применять один только порог. Сценарий с отсутствующими обязательными значениями экспортирует причины исключения.

validate формирует measurements.csv и validated.xlsx с очищенными строками, а также validation.csv с замечаниями. При ошибках в строках обе команды сохраняют только отчёт о проверке и возвращают код 2. Ошибки формата файла и конфигурации выводятся в терминал. При предупреждениях расчёт продолжается.

## Как устроен расчёт

- hec_screen/schema.py определяет поля и явные преобразования единиц. dataset.py читает таблицы, проверяет значения и ссылки, обнаруживает повторы и ведёт журнал валидации.
- screening.py выбирает по одному сопоставимому наблюдению на свойство и образец. После фильтрации строит матрицу свойств, масштабирует её столбцы min–max и умножает матрицу на вектор нормированных весов. Анализ чувствительности варьирует каждый положительный вес на ±20% при фиксированном пуле кандидатов.
- plots.py создаёт три PNG с Matplotlib. __main__.py связывает этапы с CLI и экспортирует результаты.

Главный результат — shortlist.csv или лист Shortlist в screening.xlsx. Rankings содержит весь рейтинг с каноническими и нормированными значениями. Criteria фиксирует контекст измерений, пороги, веса и диапазоны, Exclusions показывает причины исключения после фильтров метаданных. Evidence связывает расчёт с исходными значениями, единицами, строками входа, DOI и местом в публикации. Summary содержит размеры пула, Sensitivity — баллы и позиции при изменении весов, Validation — журнал импорта. Все эти таблицы также доступны как CSV. Сортировка по material_id разрешает порядок отображения одинаковых рангов при ограничении --top. Для CSV из внешних источников при открытии в Excel импортируйте текстовые колонки как текст.

## Проверенный пример и границы

Из семи высокоэнтропийных фторитовых цирконатов после фильтрации метаданных три имеют оба значения в выбранных сериях. Сценарий использует пористостно-скорректированную thermal conductivity при 25 °C и thermal expansion coefficient при 1000 °C. При весах 0.65 и 0.35 порядок — **SGDETZO (1.000000), GDHETZO (0.296610), GDHEYZO (0.278571)**. SGDETZO занимает первое место во всех пяти сценариях весов. В двух сценариях второе и третье места меняются. Числа исходных свойств сверены с Table 2 первичной работы. [Huang et al., Coatings, 2026](https://www.mdpi.com/2079-6412/16/1/79)

Результат относится к трём объёмным образцам и выбранным учебным критериям. Для вывода о пригодности покрытия нужны совместимые данные о теплопроводности при рабочих температурах, термоциклировании, адгезии и взаимодействии с подложкой. Значения с графиков не оцифровывались. Интерполяция требует достаточного ряда измерений в тех же условиях, поэтому демонстрационный расчёт её не использует. Точный шаблон потока для обмена между группами нужно сверить с преподавателем при его получении.
